0.11 ZF121：振金的合金冶炼炉配方（+ 补两处标签地基 + 拆一个能量常量的雷）

用户原话（第一版）：「振金合金冶炼炉配方；1硬质钛合金+8热力金属+2高碳钢+3银锭+12金锭
粗振金+钻石+2下界合金碎片+1红石粉 14500Fe/t 产出1振金」
用户原话（改口·最终）：「对不起刚才忘了合金炉的限制 这是新振金合金冶炼炉配方；
1硬质钛合金+8热力金属+2高碳钢+3银锭+12金锭 粗振金+2下界合金碎片14500Fe/t 产出1振金」

配方：硬质钛合金×1 + 热力金属×8 + 高碳钢×2 + 银锭×3 + 金锭×12（5 个输入槽）
      粗振金×1 + 下界合金碎片×2（2 个消耗槽）→ 振金锭×1，600 tick、14500 FE/t
      = 一件 8,700,000 FE（时长用户没给 ⇒ 沿用本机规格 30 秒）

① 消耗品从 4 样收窄成 2 样 ⇒ 槽位数一个都没动（仍 5 输入 / 3 输出 / 2 消耗槽）。
   我按第一版已经把消耗槽扩到 4 个、并撤了菜单那层门，用户改口后把槽位改动整个撤掉；
   两代改动留档在 _zf121_java_v1.py，并做成可验证的反推证明（当前盘 = 改前件 + v1 + v2 + 最终版，
   四代同堂逐字节回得去，6/6 通过）。

② 两处地基先补：硬质钛合金（ZF104）与热力金属（ZF45）本来都不在 #c:ingots 里，
   而输入槽只收这个标签 ⇒ 这两样放都放不进去、配方永远开不了工，静态检查看不出来。
   登记进 GenCommonTags.py 的 ALLOYS 表（故意没并进 c:ingots/titanium_alloy —— 那格是配方②的
   输入，并进去会变成「硬质钛合金 → 硬质钛合金」的复制漏洞，探针③d 在盯）。

③ 顺带补掉两处「表 ↔ 盘」漂移（§4.93 第 3 次）：ZF114 手写的 c:raw_materials/vibranium、
   ZF119 手写的 c:ingots/vibranium 都没登记进表 ⇒ 生成器一跑父标签里那两行就被静默抹掉
   （第一次跑实测到的）。振金登记进 METALS 表（锭 + 粗矿、没有矿石方块）⇒ 反向体检从
   「3 份手写文件」变成 item/block 类手写标签 = 0 份；并给生成器补了 stdout UTF-8
   （它原来一 print 那句警告就 GBK 崩栈，结论永远看不到）。

④ 菜单那层门撤掉：ZF49 的「消耗槽目前放不了东西」在 ZF111 放开方块实体之后还留在菜单里
   （mayPlace 恒 false）⇒ 手动一个都放不进去（只有管道/漏斗塞得进），而 ZF111 与本轮两条配方
   都要求消耗槽里有东西 —— 那是条死路。现在交给 isItemValid 判（没激活照样 false、垃圾照旧
   进不去），并让消耗品也能 shift 点击。

⑤ 探针当场抓到一个真雷（新雷 §4.100）：星璨钢那条原来借 MAX_ENERGY_PER_TICK 当自己的每 tick
   耗电（那个常量是"全表最贵那条"的意思）⇒ 本轮把它抬到 14500 时星璨钢也偷偷从 12000 变成
   14500（用户 ZF111 给的是 12000），而三处静态检查全绿、只有真游戏跑出来才现形
   （实扣 7,206,500、一轮跑不完、输出不是 3 个）⇒ 两条数各拆各的常量
   （STAR_STEEL_ENERGY_PER_TICK / VIBRANIUM_ENERGY_PER_TICK），配方表不许引用 MAX。

证据：
- 探针 Zf121Check.java（真 runServer）73 项 ALL OK（标签 / 配方表 / 门禁 / 缺料不开工 /
  跑满一轮 8,700,000 FE 分毫不差 / 防复制 / 老配方 800、星璨钢 12000）
- build/zftools/check/Zf121Check.java（24166 B，sha1 5c59ee9d…，先抄后删）
- _zf121_verify.py 常驻 130 项全绿
- 反证刀 K166~K177 十二把，每把都咬住指定的那一条检查
- 全门快照 _zf121_gatesnap.py

活体数字：语言键一个都没加、没删（仍 454 —— 那个数并行那条线刚从 449 加上去 5）

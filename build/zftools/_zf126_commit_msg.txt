0.11 ZF126：大型柴油发电机的 FE 缓冲 7200 → 18000（+ 界面上画出来）

用户原话（附一张游戏内截图：悬浮框标题「柴油发电机接线口」、里面一行「柴油 7.49B」）：
「这个加个fe缓存 18k的fe」

一、做了什么
  ① 缓冲 7200 → 18000：DieselGeneratorBlockEntity.MAX_ENERGY = 18_000。
     ZF125 那版是 `MAX_ENERGY = ENERGY_PER_TICK`（我自定的「正好 1 tick 的产量」7200，
     当时挂在 §9 待确认）—— 用户看过界面之后点名 18k ⇒ 它现在归到"用户给的数"里。
  ② 与产量**解耦**：两个数各是各的常量，以后改 ENERGY_PER_TICK 不会再顺手把缓冲改掉
     （§4.97「一个常量被两处用」那一课的同类坑）。
  ③ 界面上多了一根能量条（EnergyBarPart，12×52 竖条）：用户没点名要条，但那个数原本是
     界面外的内部数字，玩家没法确认 18k 生效 ⇒ 画出来（不想要删三行）。
     柴油罐与工作指示灯都还在 —— 加东西不许挤掉原来的。
  ④ 语言一个键都没加（能量条的悬停文案用共享键 gui.potato_s_t.energy）⇒ 四语言仍 476 键 ×4，
     零份键数耦合的门需要 retarget。

二、18k 的语义（hasRoom 判据一字未动）
  缓冲空时能顶 2 tick 的产量（2×7200 = 14400 ≤ 18000）；第 3 tick 起「装不下整整一 tick」
  就暂停烧柴油 —— 电网短暂抽不动时不白烧油，也不会把已经发出来的电扔掉。

三、证据
  · 探针 Zf126Check（真服务端）19 项全绿：常量 18000 / 产量仍 7200 / 两者不相等 /
    照图纸搭 30 格成型 / 空缓冲连跑 3 tick（7200 → 14400 → 第 3 tick 停，状态 OUTPUT_FULL，
    这 3 tick 只烧 2 mB 柴油）/ 抽走 7200 后又能发一 tick（柴油 98 → 97）/ 全程峰值不超 18000 /
    抽 999999 只拿到真实的 14400 / 抽干后再抽是 0 / 缓冲只出不进。
  · _zf126_verify.py 31 项：常量与解耦 / 注释点名用户原话 / **五个逻辑方法逐字节未变**
    （serverTick / pushEnergy / hasRoom / recheckStructure / applyPort）/
    界面构造器 = 改前件 + 那一段 EnergyBarPart / 导入只多一行 / 四语言仍 476 键且键集合与改前件逐键相同。
  · 反证刀 K199~K204 六把，逐把咬中指定检查。
  · 往轮判据只动了一处：_zf125_verify.py 的 B4（原来断言「缓冲 = 1 tick 的产量」）。
  · 本轮没有新成品：release\ 一个字没动。

0.11 ZF146：星轨坠的仪式状态搬进存档 —— 修「中途退出就不会落下 / 再次进入不能用了」

根因（别人反馈、用户转述）：仪式状态放在 static Map 里，而 Ritual 还攥着一个 ServerLevel 引用。
单机「退回标题界面再进同一个世界」时类加载器与静态字段活着、世界却换了一茬：
① tick() 拿上一个服务器那个停摆的时钟算 remain ⇒ 冻住、永远走不到 0 ⇒ 陨石永不生成；
② use() 看新世界的时钟，过了取消窗口恒判「已锁定」，而那条死记录又永远删不掉 ⇒ 道具永久失效。

修法：RitualData extends SavedData（<存档>/data/potato_s_t_starfall.dat，与 raids.dat 同处），
记录里只留维度的 key，每 tick server.getLevel(ritual.dimension) 现查、
server.overworld().getDataStorage().computeIfAbsent(...) 现取 —— 类里从此没有任何
能活过一次世界切换的世界引用；通报进度（Next / Warned）一起存，免得读盘补发过时通报。

证据：两次开服对照（同一份探针，改前 / 改后都编得过、都跑得起来）
  · 改前第二趟 3 条红：存档里没有仪式数据 / 进世界右键「被拒」失败、上一场凭空消失 /
    等到预期落地后 251 tick 也没等到陨石（用户报的「不会落下」当场复现）
  · 改后第二趟全绿：世界时间 1151 退出、陨石正好在 1451 生成（差 0 tick、威力 14、y=200），
    落地炸掉平台 121 格，落地后再右键又能用了（耐久 0→1）、进世界那次右键被拒（0→0）
  · 存档 191 B，gzip 解开后能按 NBT 字节序找到维度名与 endTick=1451 的大端 int64
